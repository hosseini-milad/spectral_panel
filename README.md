# پنل اسپکترال

نسخهٔ اولیهٔ مستقل با React، TypeScript و Vite در برنچ `panel`.
فایل‌های پنل، شامل `src/` و `package.json`، مستقیماً در ریشهٔ این برنچ قرار دارند. بک‌اند و پروژهٔ علمی در برنچ `main` نگهداری می‌شوند؛ ادغام این دو برنچ بخشی از این ساختار نیست.
پنل دارای پوستهٔ فارسی و راست‌به‌چپ و صفحه‌های ماک «نمای کلی»، «روزها و چانک‌ها»، «عملیات و پردازش» و «تصاویر و نمودارها» است. داده‌ها ثابت و صریحاً نمایشی‌اند؛ هنوز داده‌ای از بک‌اند دریافت یا عملیات واقعی اجرا نمی‌شود. سایر صفحات در حد پوسته باقی مانده‌اند.

## عملیات و پردازش

مسیر `/#/operations` ابتدا انتخاب روز را می‌خواهد. لینک `/#/operations?day=2026-11-05` همان روز نمونه را از پیش انتخاب می‌کند. روز ناموجود پیام روشن دارد و اجرا تا انتخاب یک روز دارای داده غیرفعال است.

مسیر نمایشی: انتخاب روز ← نرمال‌سازی ← نمونه‌برداری/کاندید ← انتخاب نماینده ← ساخت گراف و مولفه. هر گام پس از موفقیت گام قبلی فعال می‌شود. «اجرای همهٔ مراحل» مراحل باقی‌مانده را پشت‌سرهم اجرا می‌کند و مراحل موفق را تکرار نمی‌کند. خروجی‌ها، درصد پیشرفت و لاگ‌ها فقط ماک‌اند.

- هر مرحله وضعیت، ورودی/خروجی، شناسهٔ اجرای ماک و زمان نمایش دارد. نتیجهٔ مرحلهٔ اجرا‌نشده با «—» نشان داده می‌شود.
- روز و تنظیمات در حین اجرا قفل‌اند. پس از اولین اجرا، نسبت‌های نمونه‌برداری/نماینده برای سازگاری نتایج ثابت می‌مانند؛ برای تغییرشان «نمایش جدید» شروع کنید.
- توقف، فقط شبیه‌سازی محلی را متوقف می‌کند. تلاش مجددِ مرحلهٔ نیمه‌تمام، از ابتدا نمایش داده می‌شود؛ مراحل موفق قبلی حفظ می‌شوند.
- در «تنظیمات سناریو»، حالت خطا در نمونه‌برداری را می‌توان امتحان کرد؛ ادامهٔ زنجیره متوقف می‌شود. با انتخاب «اجرای موفق» و اجرای دوباره، فقط مراحل باقی‌مانده نمایش داده می‌شوند.
- تغییر روز، خروج از صفحه یا بازخوانی، اجرای نمایشی و تایمرهای آن را پاک می‌کند. لاگ‌ها به وقت تهران‌اند و لاگ واقعی worker نیستند.
- فقط چانک‌های موجود در نمونه وارد این مسیر می‌شوند. نتیجهٔ این سناریوی مستقل، وضعیت صفحهٔ روزها یا سایر داده‌های ماک را تغییر نمی‌دهد. هیچ حذف یا `force` واقعی وجود ندارد.

منطق شبیه‌سازی در `src/hooks/useMockPipeline.ts` و تعریف گام‌ها/شمارش‌های نمونه در `src/data/operations.ts` است. این ترتیب، طرح رابط درخواستی است و نگاشت یک‌به‌یک به دستورات بک‌اند نیست؛ در بک‌اند فعلی ساخت گراف پیش‌نیاز انتخاب نماینده است و pooling می‌تواند نماینده و مولفه را با هم بسازد. هنگام اتصال API، باید همین وابستگی‌ها و قرارداد parserهای واقعی حفظ شوند، نه اینکه ترتیب علمی برای تطبیق با طرح ماک تغییر کند. هنوز job واقعی ثبت نمی‌شود.

اسکرول‌بارها در کل پنل خطی و نازک‌اند: در Chromium/WebKit عرض و ارتفاع ۴ پیکسل با مسیر شفاف، و در Firefox حالت استاندارد `thin`. رنگ با تم روشن/تیره هماهنگ است؛ قواعد مشترک در `src/theme.css` قرار دارند.

## نمای کلی مدیریتی

صفحهٔ اصلی `/#/` شاخص‌های عمومی SIEM را برای یک روز نمونه نشان می‌دهد: حجم رویداد، EPS تخمینی روزانه، منابع در دسترس، نرخ پذیرش داده، پیشرفت پردازش و موارد باز عملیاتی. روند حجم ورودی، سلامت گروه‌های منبع، پوشش مراحل و جدول روزهای اخیر هم ارائه می‌شوند. تم روشن/تیره و نمایش موبایل پشتیبانی می‌شود.

- انتخاب روز در آدرس نمای کلی ذخیره می‌شود، مثلاً `/#/?day=2026-11-03`؛ بازگشت از جزئیات، انتخاب روز گزارش را حفظ می‌کند.
- همهٔ لینک‌های جزئیات کارت‌ها، منابع، موارد پیگیری و نمودار به `/#/days?day=YYYY-MM-DD` می‌روند. ستون‌های روند و ردیف روزهای اخیر، تاریخ همان روز را منتقل می‌کنند.
- صفحهٔ روزها تاریخ را از query می‌خواند، صفحه‌بندی را روی همان روز قرار می‌دهد و آکاردئون آن را باز می‌کند. بازخوانی و Back/Forward نیز تاریخ را حفظ می‌کنند. انتخاب روز از جدول یا تقویم همین صفحه، آدرس را به‌روز می‌کند.
- تاریخ نامعتبر با پیام روشن رد می‌شود؛ تاریخ معتبرِ بدون داده، حالت «داده نداریم» دارد.

تعریف شاخص‌ها در `src/data/overview.ts` است. EPS از رکوردهای موجود تقسیم بر ۸۶٬۴۰۰ ثانیه به دست می‌آید و نرخ لحظه‌ای نیست. پذیرش داده، فقط نسبت رکورد نرمال‌شده به ورودی چانک‌هایی است که نرمال‌سازی را گذرانده‌اند؛ چانک‌های اجرا‌نشده از این نسبت کنار گذاشته می‌شوند. پیشرفت پردازش، چانک‌های ناموجود را صفر منظور می‌کند.

پروفایل‌های منبع (شبکه، هویت، DNS، میزبان و ابر)، وضعیت دریافت و موارد پیگیری همگی سناریوی ماک‌اند؛ کشف واقعی collector یا هشدار امنیتی نیستند. تعداد رکورد منابع با تخصیص وزن‌های ثابت به مجموع روز منطبق می‌شود. اولویت «بالا/متوسط» برای پیگیری عملیاتی است، نه شدت حمله. وضعیت امنیتی و مدل/مرجع ارزیابی نشده‌اند؛ MTTD/MTTR، حادثهٔ تأییدشده و پوشش قواعد تشخیص بدون دادهٔ معتبر به‌صورت عدد ساختگی نمایش داده نمی‌شوند.

## تصاویر و نمودارها

مسیر `/#/visualizations` سه نمودار SVG تعاملی دارد: حجم دادهٔ چانک‌ها، پوشش مراحل پردازش و توزیع وضعیت چانک‌ها. بدون فیلتر اضافی، تمام چانک‌های موجودِ روز انتخاب‌شده نمایش داده می‌شوند؛ روز اولیه همان آخرین روز مجموعهٔ ماک است.

- روز را از تقویم شمسی یا ورودی تاریخ میلادی انتخاب کنید. فیلتر چانک، وضعیت و مرحله فقط پس از «اعمال فیلتر» روی نمودارها اثر می‌گذارد.
- ستون‌ها برای انتخاب چند چانک، لغزنده‌ها برای انتخاب بازهٔ شمارهٔ چانک، مرحله‌ها و بخش‌های حلقه برای فیلتر مشترک قابل انتخاب‌اند. Enter و Space نیز انتخاب می‌کنند. انتخاب‌ها با هم اشتراک می‌گیرند؛ کلیک دوباره یا حذف برچسب، فیلتر مربوط را برمی‌دارد.
- «بازنشانی» آمار کل همان روزِ اعمال‌شده را برمی‌گرداند. نبود داده و اشتراک خالی، حالت‌های جداگانه دارند.
- راهنمای سری‌های حجم داده برای نمایش/پنهان‌کردن سری است و دادهٔ انتخابی را تغییر نمی‌دهد؛ حداقل یک سری نمایان می‌ماند.
- هر نمودار زمینهٔ فیلتر خودش را حفظ می‌کند تا امکان تغییر انتخاب باقی بماند؛ کارت‌های آمار، جدول و CSV اشتراک تمام فیلترها را نشان می‌دهند. دامنه و متادیتای SVG به‌صورت صریح ذخیره می‌شود.
- SVG هر نمودار، فیلترها، شناسه‌های اجرای ماک، محدودهٔ زمینه و تم را دارد. CSV جدول انتخابی شامل روز و شناسه‌های اجرای ماک است؛ نام همهٔ فایل‌ها با `mock-` شروع می‌شود.

رسم و فیلتر فقط در مرورگر روی داده‌های ثابت انجام می‌شود؛ نمودار طیفی یا سنجهٔ علمی جدید محاسبه نمی‌شود. هنگام اتصال واقعی، محاسبات سنگین و فیلتر داده‌های حجیم باید سمت سرور و worker انجام شوند.

## تم روشن و تیره

دکمهٔ تم در هدر، ظاهر همهٔ صفحه‌ها را تغییر می‌دهد. انتخاب در `localStorage` با کلید `spectral-theme` ذخیره می‌شود؛ در اولین بازدید ترجیح سیستم استفاده می‌شود. اگر ذخیره‌سازی مرورگر در دسترس نباشد، تغییر تم در همان بازدید کار می‌کند. متغیرهای رنگ مشترک و سازگاری صفحهٔ روزها در `src/theme.css` تعریف شده‌اند.

## صفحهٔ روزها و چانک‌ها

مسیر `/#/days` شامل هفت روز نمونه تا ۱۴ آبان ۱۴۰۵ است:

- خلاصهٔ رکوردها، چانک‌ها و روزهای تکمیل‌شده؛ فهرست روزها با جست‌وجوی تاریخ شمسی/میلادی، فیلتر وضعیت و صفحه‌بندی.
- تقویم شمسی با جابه‌جایی ماه، انتخاب روز مشخص و حالت بدون داده.
- لینک مستقیم به تاریخ مشخص، مثلاً `/#/days?day=2026-10-30`، با بازشدن روز در صفحهٔ صحیح جدول.
- جزئیات آکاردئونی روز، جدول چانک‌ها با جست‌وجو، فیلتر، صفحه‌بندی و جزئیات مراحل/خطا.
- گزارش همان روز با پوشش مراحل، توضیح برآورد و دریافت JSON شامل شناسه‌های اجرای نمونه.

داده‌ها در `src/data/days.ts` ثابت و قابل جایگزینی با سرویس آینده‌اند. برآورد تعداد رکورد روز از میانگین چانک‌های موجود به دست می‌آید و تضمین کامل‌بودن داده نیست. چانک پارتیشن پردازش است، نه ساعت. هیچ درخواست API، حذف، بازسازی، اجرای علمی یا تشخیص حمله انجام نمی‌شود.

## اجرا

Node.js نسخهٔ ۲۲.۱۲ یا جدیدتر (محیط فعلی: ۲۴) و npm لازم است.

```sh
cd /workspace/spectral_project
npm ci
npm run dev
```

پورت پیش‌فرض Vite برابر ۵۱۷۳ است. برای بررسی نسخهٔ تولید:

```sh
npm run build
npm run preview
```

`build` بررسی سخت‌گیرانهٔ TypeScript را نیز اجرا می‌کند. مسیرها hash-based هستند؛ بازخوانی و لینک مستقیم به صفحات به تنظیم fallback سرور نیاز ندارند. فونت فارسی Vazirmatn از بستهٔ npm و به‌صورت محلی ارائه می‌شود؛ CDN، سرویس فونت و کتابخانهٔ نمودار در این نسخه وجود ندارد.

## ساختار

```text
src/
  components/     # پوسته، days/، overview/، operations/ و visualizations/
  config/         # تعریف مرکزی منوها و توضیح صفحات
  data/           # داده‌های ماک و منطق انتخاب/خروجی نمودارها
  hooks/          # اجرای مرحله‌ای و محلی سناریوی ماک
  lib/            # تم و اندازهٔ واکنش‌گرای SVG
  pages/          # صفحه‌های روزها، نمودارها و پوستهٔ سایر بخش‌ها
  App.tsx         # پوسته، مسیریابی و منوی موبایل
  main.tsx        # نقطهٔ ورود و فونت‌ها
  styles.css      # سبک‌ها و قواعد واکنش‌گرا
  theme.css       # رنگ‌های مشترک و تم روشن/تیره
docs/
  panel-plan.fa.md # نقشهٔ صفحات، جریان کار و نیازهای API
```

منوی موبایل با dialog بومی مرورگر، حبس فوکوس، بستن با Escape و بازگشت فوکوس به دکمهٔ منو کار می‌کند. لینک پرش به محتوا و وضعیت صفحهٔ فعال برای پیمایش با صفحه‌کلید وجود دارد.

## بک‌اند

برای دیدن Swagger، بک‌اند برنچ `main` باید به‌صورت سرویسی جداگانه در پورت ۸۰۰۰ اجرا شود؛ فایل‌های بک‌اند در این برنچ نیستند. Vite مسیرهای `/api`، `/swagger` و assetهای Swagger را به همان سرور proxy می‌کند. خود پوسته بدون بک‌اند قابل استفاده است. `vite preview` این proxy توسعه را ارائه نمی‌کند؛ برای استقرار واقعی، reverse proxy همین مسیرها باید در سرور تعریف شود.

هیچ تغییری در Django، MongoDB، دستورهای کنسولی و منطق علمی ایجاد نشده است. سیاست احراز هویت و دسترسی، مسیریابی استقرار و اتصال داده‌ها باید پیش از انتشار عمومی تعیین شوند. این نسخه قابلیت ورود یا حفاظت دسترسی پیاده‌سازی نمی‌کند.

جزئیات مرحله‌های بعد در [طرح توسعه](docs/panel-plan.fa.md) آمده است.

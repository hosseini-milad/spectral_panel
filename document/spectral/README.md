# فاز اول طیفی ـ نسخهٔ اجرایی جدید

مسیر طیفی از نو برای گراف‌های مؤلفه‌محور نوشته شده است. معماری کلی مطابق دو
شماتیک پروژه باقی می‌ماند، اما اجرا فازبه‌فاز است. این فاز فقط تحلیل طیفی و
تولید ورودی معتبر برای eigenvector-aware message passing را اجرا می‌کند.

## فرمان روزانه

```sh
python -u manage.py spectral_analysis --day 2026-06-21 --force
```

این فرمان گراف‌های چانک و گراف مؤلفه‌های روز را از نسخهٔ سازگار می‌خواند،
داخل مؤلفه‌های متصل تحلیل ویژه انجام می‌دهد و گزارش آماری و شماتیک می‌سازد.
برای بررسی اولیهٔ یک چانک:

```sh
python -u manage.py spectral_analysis --day 2026-06-21 --scope chunks --chunk-index 0 --force
```

## خروجی و معنای آن

| بخش | وضعیت این فاز |
|---|---|
| لاپلاسین نرمال‌شده، مقادیر و بردارهای ویژه | اجرا می‌شود؛ حل کامل محدود یا sparse بر حسب اندازه |
| تغییر علامت و چرخش پایهٔ ویژه | ورودی‌های مبتنی بر projector و mask تولید می‌شوند |
| گرهٔ منفرد | نبودِ بردار غیرصفر ثبت می‌شود؛ صفر مشاهده‌شده جعل نمی‌شود |
| فضای ویژهٔ تکراری | گروه کامل تا سقف بودجه حفظ یا صریحاً کنار گذاشته می‌شود |
| ماژول eigenvector-aware message passing | بازنویسی و آزمون شده؛ در تحلیل طیفی آموزش داده نمی‌شود |
| Autoencoder، Ridge و امتیاز ناهنجاری | فازهای بعد؛ اجرا نشده |
| دو یا چند سطح بالاتر از متاکامپوننت | جدول آمادگی و سناریوی اندازه؛ گراف و طیف محاسبه‌شده اعلام نمی‌شود |
| دقیقه/ساعت/روز | زمان واقعی باید جدا ممیزی شود؛ چانک به ساعت فرضی تبدیل نمی‌شود |

بودجهٔ پیش‌فرض ۸ بردار و حداکثر ۳۲ بعد برای تکمیل فضای تکراری است؛ مؤلفهٔ کوچک
طبیعتاً ابعاد کمتری دارد. معیارهای residual، تعامد، کرنل و دامنهٔ مقدار ویژه
پیش از انتشار کنترل می‌شوند. هیستوگرام و آنتروپی کامل از طیف ناقص ساخته نمی‌شوند.

مستندات هر گراف:
`document/spectral/layerN/<day>/<chunk-N-or-whole-day>/<graph-key>/runs/<run-id>/`

- `spectral_summary.json/txt` و `metrics.csv`: جدول معیار با واحد، تعریف و وضعیت.
- `spectral_blocks.json` و `blocks.csv`: نتایج هر مؤلفه و شناسهٔ فرزند/والد.
- `spectral_features.npz`: بردارها، مقادیر، maskها، ویژگی‌های ناوردا و ترتیب گره‌ها.
- `node_lineage.json`: ارتباط با داده/مؤلفهٔ مبدأ.
- `spectral_overview.png/svg`: اندازهٔ مؤلفه‌ها، طیف موجود، بردار ویژه و صحت عددی.

جمع‌بندی کل فاز:
`document/spectral/phase1/<day>/runs/<run-id>/`

در این پوشه `phase_manifest.json`، `graph_summary.csv`، `hierarchy_readiness.csv`،
`phase_summary.txt` و `phase_overview.png/svg` ذخیره می‌شود. HTML و lineage_page
تولید نمی‌شوند. `--force` نسخهٔ جدید می‌سازد و نسخه‌ها و نتایج قبلی را حفظ می‌کند.

## نگاشت سلسله‌مراتب و سطوح بالاتر

لایهٔ ۱، گراف کاندیدهای جریان است؛ لایهٔ ۲، گراف روزانهٔ مؤلفه‌ها. لایهٔ ۳
فعلاً عضویت متاکامپوننت‌هاست و گراف معنادار میان آن‌ها هنوز موجود نیست.
سطوح ۴ و ۵ پیش‌فرض، دو سطح پیشنهادی بالاتر از متا هستند. با فرض نسبت فشرده‌سازی
۰٫۵، از ۱۷۳۱ گروه، سناریوی ۸۶۶ و سپس ۴۳۳ واحد به دست می‌آید؛ این فقط برآورد است،
نه نتیجهٔ تجمیع یا تحلیل ویژهٔ اجراشده. تعداد واقعی در جدول از نسخهٔ دیتابیس
خوانده می‌شود و فرض با `--planning-ratio` مشخص است.

برای ساخت لایه‌های واقعی بالاتر، قاعدهٔ تجمیع، حفظ یال مرزی، وزن/جرم گره و
نگاشت عضویت باید پیاده و ارزیابی شود. تحلیل فعلی گراف‌های موجود منتظر آن نمی‌ماند.
به فرامؤلفه‌های فعلی که connected component هستند، یال زمانی/ارتباطی فرضی اضافه نمی‌شود.

کدهای قدیمیِ فایل/ساعت ترتیبی، مدل‌ها و فرمان‌های وابسته حذف شده‌اند؛ داده‌های
گذشتهٔ MongoDB و فایل وزن‌های قدیمی پاک نشده‌اند. مسیر یادگیری آینده با آن
checkpointها سازگار فرض نمی‌شود. جزئیات قرارداد در `spectral_learning/README.md`
قرار دارد. مستندات planning حفظ شده‌اند و سابقهٔ طراحی‌اند، نه نتیجهٔ حل عددی جدید.

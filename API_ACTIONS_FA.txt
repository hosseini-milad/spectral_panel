REST API مستقل و Swagger
=======================

ساختار
کد API در پوشهٔ api ریشهٔ پروژه است: registry، views، serializers، jobs، worker، urls و تست‌ها. API قدیمیِ داخل ingestion به api/legacy_ingestion منتقل شده و importهای router قدیمی تطبیق داده شده‌اند. هیچ کامند یا الگوریتم علمی موجود تغییر نکرده است. مسیرهای جدید، همان کامندها را در worker جدا اجرا می‌کنند.

راه‌اندازی، هر دستور تک‌خطی و از ریشهٔ پروژه

git pull origin main
python -m pip install -r requirements.txt

MongoDB سیستم باید مانند قبل در دسترس باشد. نیازی به Redis، Celery یا migration دیتابیس SQL نیست. در یک ترمینال worker را روشن نگه دارید
python -u manage.py run_api_worker

در ترمینال دیگری وب‌سرور را اجرا کنید
python -u manage.py runserver 127.0.0.1:8000

Swagger بدون احراز هویت
http://127.0.0.1:8000/swagger/

Schema
http://127.0.0.1:8000/api/schema/

فایل‌های CSS/JS سوگر همراه وابستگی sidecar محلی نصب می‌شوند؛ CDN و collectstatic برای این راه‌اندازی لازم نیست. اگر MongoDB خاموش باشد Swagger همچنان باز می‌شود، ولی صف و عملیات داده‌ای پاسخ503 می‌دهند. برای hostname دیگر، DJANGO_ALLOWED_HOSTS با مقادیر جداشده با کاما تنظیم شود.

الگوی عملیات
POST به route هر اکشن با JSON؛ پاسخ202 یعنی درخواست در صف ثبت شده، نه اینکه عملیات کامل شده است. پاسخ job.id و detail_url و logs_url دارد. اجرای واقعی در worker انجام می‌شود؛ بستن مرورگر آن را متوقف نمی‌کند. پارامترهای JSON همان نام کامند با underscore هستند؛ مثلاً --source-file به source_file و --chunk-index به chunk_index تبدیل می‌شود. پارامترهای لیستی مانند fit_days و seeds آرایهٔ JSON هستند. days در normalize-parquet مطابق کامند رشتهٔ تاریخ‌های جداشده با کاماست.

نمونه‌های مهم

POST /api/v1/actions/ingestion/ingest-parquet/
{"directory":"F:/parquet/date=2026-06-15/type=normal","batch_size":5000}
مسیر باید روی ماشین worker موجود باشد؛ مرورگر با واردکردن مسیر، فایل سیستم رایانهٔ دیگری را منتقل نمی‌کند.

POST /api/v1/actions/ingestion/normalize-parquet/
{"days":"2026-06-15","chunk_index":0,"sample_per_day":20000,"batch_size":2000}

POST /api/v1/actions/layer1/hyper-general-action/
{"source_file":"clustered-day-2026-06-17","limit":15,"force":false}
force=true همان رفتار حذف بدون پشتیبانِ تمام خروجی روز و بازسازی بازهٔ درخواستی را دارد. پیش‌فرض false است. برای ادامهٔ اجرای قبلی false نگه دارید.

POST /api/v1/actions/layer1/build-representatives/
{"day":"2026-06-15","chunk_index":0,"stage":"reps","ratio":0.1,"force":true}

POST /api/v1/actions/layer1/preview-representative-spread/
{"day":"2026-06-15","chunk_index":0}

POST /api/v1/actions/hierarchy/build/
{"day":"2026-06-15"}

POST /api/v1/actions/hierarchy/evaluate/
{"day":"2026-06-15"}

POST /api/v1/actions/spectral/analyze/
{"day":"2026-06-15","scope":"all"}

POST /api/v1/actions/spectral/message-passing/
{"day":"2026-06-15"}

{"experiment_bundle":"document/autoencoder/layer1/2026-06-20/whole-day/neighborhood_learning/runs/8d4ba293800a4d7c82c7bc6f4a5d385d","fit_days":["2026-06-15","2026-06-16"],"calibration_days":["2026-06-17","2026-06-18"],"test_days":["2026-06-19"],"seed":17,"alpha":0.01,"write":true}

فهرست کامل تمام۴۱اکشن و پارامتر/پیش‌فرض‌های واقعی
GET /api/v1/actions/
همین اکشن‌ها به صورت route مستقل در Swagger هستند؛ command دلخواه یا متن shell پذیرفته نمی‌شود.

پیگیری
GET /api/v1/jobs/
GET /api/v1/jobs/<job-id>/
GET /api/v1/jobs/<job-id>/logs/?offset=0&limit=65536
در لاگ، next_offset محل درخواست بعدی برحسب بایت است و متن فارسی درست حفظ می‌شود. خطای خود کامند در error و لاگ ثبت می‌شود. در نبود worker، درخواست queued می‌ماند و با شروع worker اجرا می‌شود.
POST /api/v1/jobs/<job-id>/cancel/ فقط اجرای هنوزدرصف را لغو می‌کند؛ اجرای فعال از HTTP قطع نمی‌شود و409 برمی‌گردد. قطع worker ممکن است مثل توقف CLI خروجی ناقص باقی بگذارد؛ وضعیت interrupted است و خودکار retry نمی‌شود.

جلوگیری از ارسال تکراری
در Swagger هدر اختیاری Idempotency-Key را برای retry یک درخواست ثابت کنید. همان کلید/پارامتر job قبلی را برمی‌گرداند؛ همان کلید با پارامتر متفاوت409 می‌دهد. برای اجرای واقعاً جدید، کلید جدید بدهید یا هدر را حذف کنید. این رفتار حذف اجباریِ تکراری بر اثر retry را جلوگیری می‌کند؛ اجرای علمی خودکار تکرار نمی‌شود.

روز و چانک، فقط خواندنی
GET /api/v1/days/
GET /api/v1/days/2026-06-17/chunks/
چانک بخش پردازشی است، نه پنجرهٔ زمانی. شمار خروجی‌ها حتی در وضعیت ناقص قابل مشاهده است.

گزارش‌ها و تصویرها
گزارش علمی و تصویر همان مسیر document قبلی را دارد و مسیر دقیق در stdout هر کامند چاپ می‌شود. لاگ و result.json خود API زیر document/api/jobs/<job-id>/ هستند.
GET /api/v1/artifacts/?path=autoencoder/layer2/2026-06-20/whole-day
GET /api/v1/artifacts/file/?path=مسیرنسبی‌فایل‌داخل‌document
لیست و دانلود محدود به document است؛ path خارج از آن رد می‌شود. عکس‌های PNG/JPEG/WebP قابل نمایش مستقیم هستند و فایل‌های دیگر دانلود می‌شوند.

صف و هم‌زمانی
دو collection جدید api_jobs و api_runtime برای صف، تاریخچه و قفل worker استفاده می‌شوند؛ دادهٔ علمی در collectionهای قبلی می‌ماند. فقط یک worker API هم‌زمان عملیات علمی را اجرا می‌کند. این قفل شامل CLIهایی که جدا در ترمینال اجرا می‌کنید نیست؛ عملیات نوشتنی هم‌پوشان را هم‌زمان از CLI و API اجرا نکنید. پیش از git pull یا تغییر وابستگی‌ها worker را متوقف کنید. بازیابی worker مرده بدون retry خودکار و با کنترل PID/زمان ساخت پردازش انجام می‌شود؛ قفل پردازش زنده ربوده نمی‌شود.

این نسخه پنل گرافیکی اختصاصی نیست؛ زیرساخت REST و Swagger آن است. احراز هویت عمداً فعلاً فعال نیست. چارچوب علمی و رفتار کامندهای قبلی حفظ شده است.

شش اکشن قدیمی نیز در دستهٔ Legacy قرار دارند؛ رفتار آن‌ها مانند CLI قدیمی است و مسیر اصلی پیشنهادی همان پارکت و چانک‌هاست. pandas و openpyxl برای حفظ پشتیبانی اکشن‌های قدیمی Excel به وابستگی‌ها اضافه شده‌اند.
